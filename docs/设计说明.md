# 设计说明（架构要点）

> PRD 在工作区 `docs/astrbot_plugin_moe_waifu_PRD.md`（跨仓库文档不入本仓库）。
> 本文件只留实现层的架构要点，写给三个月后的自己。

## 模块与数据流

```
main.py（指令/编排）
  ├─ pool.py   角色库装载（pools/*.json，data 目录唯一真源）+ 种子决定论抽取
  ├─ draw.py   萌绘契约封装（base/lora/img2img 分派）+ 立绘库决策纯函数
  ├─ card.py   纯 Pillow 竖版卡（无 astrbot 依赖，可独立测）
  └─ store.py  SQLite 五表（同步 sqlite3 + 公开方法串行化，星语同款）
```

抽卡链：`derive_seed(date,uid,salt,nonce)` → `pick_character(candidates)` →
`decision_of`（reuse_today / generate / from_pool）→ 生成时 `portrait_seed_int`
→ 萌绘 handler → `archive_portrait` 拷贝进 `portraits/<id>/` → `render_card` → 发卡。

## 关键决策（为什么这么做）

1. **立绘库不是缓存**：无淘汰、无 TTL，`portraits/` 是沉淀资产；满配额取图走
   `pool_index`（对当日恒定）→ 同群同款天然共享。萌绘 gallery 里的原图不可控
   （会被它自己的清理机制动），所以生成后必须 `shutil.copy2` 一份进自己 data 目录。
2. **硬依赖不降级**：`generate_portrait` 失败返回 None，调用方 `_produce` 发错误文案
   并返回 None——**不渲染无图卡**。`card.render_card` 对缺立绘直接抛
   FileNotFoundError 双保险。满库角色不受萌绘状态影响（取库零绘图）。
3. **种子决定论 + 可编辑库的折衷**：候选按 (pack, id) 排序后取模；用户编辑卷
   会全体重排——接受（换库不追溯，当日 draws 落库的 card_path 回看不受影响）。
4. **handler 传真实 event**：萌绘内部用会话上下文；WebUI 试画（M2，无事件）时
   要另想兜底，不能简单传 None（draw.generate_portrait 已留 event 参数）。
5. **img2img 不带 `workflow` 参数**：那是文生图槽位；图生图工作流走
   `strategy.img2img_workflow`（用户自定义 IPAdapter 工作流的远期挂点）。
6. **负面词内置兜底**：`1boy, male...` 排除男性特征 + NSFW（星语子集）；
   `draw_negative_enabled=False` 时完全不传（含内置），全权交给用户工作流。
7. **`♥` 之类装饰字形不要上卡**：多数 CJK 字体缺字渲染成方块（本次预览实测）。

## 测试

`tests/` 三个纯函数自检（pool / draw / card），直接跑、退出码即结论。
本机跑法：`uv run --no-project --with pillow python -I tests/test_<x>.py`
（裸 python 是商店桩，exit 49）。

## 注意事项

- 新增顶层模块要同步：`build_zip.ps1` 的 `$includeList`（有守卫会拦）与
  `main.py` 的 `_reload_modules()`。
- 热重载生效依赖 main 里**模块属性访问**（pool.xxx 而非 from-import 函数）。
- 打包脚本 ASCII-only（PS 5.1 非 UTF8 代码页会误解析 CJK 注释）。
