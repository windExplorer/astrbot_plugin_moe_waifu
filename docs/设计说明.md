# 设计说明（架构要点）

> PRD 在工作区 `docs/astrbot_plugin_moe_waifu_PRD.md`（跨仓库文档不入本仓库）。
> 本文件只留实现层的架构要点，写给三个月后的自己。

## 模块与数据流

```
main.py（指令/编排）
  ├─ pool.py        角色库装载（pools/*.json，data 目录唯一真源）+ 种子决定论抽取
  ├─ draw.py        萌绘契约封装（base/lora/img2img 分派）+ 立绘库决策纯函数
  ├─ card.py        纯 Pillow 竖版卡（无 astrbot 依赖，可独立测）
  ├─ store.py       SQLite 七表（同步 sqlite3 + 公开方法串行化，星语同款）
  └─ webui_api.py   工坊 Page 后端（48 条路由；handler 薄、业务在 _xxx_core）
```

抽卡链：`derive_seed(date,uid,salt,nonce,epoch)` → `pick_character(candidates)` →
`decision_of`（reuse_today / generate / from_pool，**v0.19.3 起把 `gen_source_mode`
一并传进去**）→ generate 时再经 `plan_source`
（v0.9.6 出图方式：mix 按种子概率在 from_pool / generate_i2i（模板图生图，产出照常
归档）间分配；pool=只用库存；img2img=只用模板图、**每次都现画且不受满配额短路**
（v0.19.3 修「配了只用图生图模板却一直取立绘」）；回退链见函数注释）→ 生成时
`portrait_seed_int` → 萌绘 handler（**串行队列**，`_gen_lock`，多召唤逐张画）→
`archive_portrait` 拷贝进 `portraits/<id>/` → `render_card` → 发卡。

**决策可解释（v0.19.4）**：`draw.explain_decision(mode, decision, pool_size, quota,
has_ref, i2i_prob, roll)` 把「这次为什么这么出图」翻成一句中文（满配额取库 / 掷点未命中 /
没指定出卡源回退 / img2img 满配额仍现画 / 库存文件丢失改生成 …），随签写进
`draws.decision_note` 与 `draw_events.decision_note`（老库靠 `_MIGRATIONS` 的
PRAGMA+ALTER 补列），同时 `logger.info` 一条。工坊记录页的「决策」列悬停可看原因、
详情抽屉有「为什么」一行、流水也有决策列，调试模拟同样返回 `decision_note`。
排查「配了却没生效」先看这一句，别再翻代码猜。

**当日复用 vs 每次都现画（v0.19.6）**：`reuse_today` 判断的是 `portraits` 表里
**该角色当天**是否已生成过立绘（同角色同一天人人同款 → 省算力），与某个 QQ 的
`draws` 无关——所以「调试重置了今日签，再抽还是当日复用」是正常的：重置只删签，
不清该角色今天的立绘。两条修正：① `img2img`（只用图生图模板）连 `reuse_today`
也不参与，每次都按出卡源现画；② 调试页「重置」顺手把该角色今日立绘移入回收站
（`reset_char_day`），重置后重抽会真的重新生成。记录页的决策文案也从
「当日复用立绘」改成「当日已有立绘（复用）」，避免被读成「这个用户今天抽过了」。

**危险操作分域 + 回收站（v0.19.5 事故）**：调试页原来的「清空老婆立绘库」作用对象是
**角色**（`portraits` 表 `char_id` 维度、所有用户共用，也就是「角色详情」里那面立绘墙），
却被摆在「今日签操作（某个 QQ + 今天）」那一排，用户以为是清某个用户的抽取记录，
点了之后该角色 5 张立绘连文件一起没了（当时是 `unlink`，不可恢复）。三条修正：
① 两个作用域彻底分开——「按角色清库（危险 · 与 QQ 用户无关）」独立成卡、点名角色与
张数，并明确指向「按用户清签」；用户真正想要的「清所选 QQ 的全部签」补成快捷按钮
（`debug/clear_draws` 不带 date）；
② 破坏性动作的**文件一律 `_trash_files()` 移进 `data/_trash/<时间戳>/`**（保留原相对
路径，误点可手动搬回），不再 `unlink`；`draws`/`portraits` 行照删，配额与统计立即正确；
③ `debug/clear_portraits` 服务端强制 `confirm=true`，前端两段确认文案带角色名与张数。

`epoch` 是「重置轮次」（`user_epochs` 表，v0.9.5）：调试清签（`clear_draws`）对受影响
用户 +1，种子整体重派——清签重抽不再回到同一个人（用户明确要求）；卡片印象语按签
从 `entry.quotes` 池确定性选一句（`pool.pick_quote`）。

**两张表、两种口径**（v0.9.0）：

| 表 | 语义 | 谁写 |
| --- | --- | --- |
| `draws` | 当前状态，PK `(user_id,date)`，重抽 `ON CONFLICT DO UPDATE` **覆盖** | `upsert_draw` |
| `draw_events` | 事件流，**只追加**，含 `kind=first/reroll`、种子、角色快照、立绘路径 | `upsert_draw` 同事务双写 |

统计一律以 `draws` 为准（一人一天只计一次）；重抽轨迹从 `draw_events` 读。
另有 `debug_history`（调试查询 / 动作审计，环形 200 条）。

## 关键决策（为什么这么做）

1. **立绘库不是缓存**：无淘汰、无 TTL，`portraits/` 是沉淀资产；满配额取图走
   `pool_index`（对当日恒定）→ 同群同款天然共享。**例外**：`gen_source_mode=img2img`
   时满配额也照画（用户口径「只用图生图模板」），代价是库持续增长、无淘汰——
   想收住就在工坊删图或改回 mix/pool。萌绘 gallery 里的原图不可控
   （会被它自己的清理机制动），所以生成后必须 `shutil.copy2` 一份进自己 data 目录。
2. **硬依赖不降级**：`generate_portrait` 失败返回 None，调用方 `_produce` 发错误文案
   并返回 None——**不渲染无图卡**。`card.render_card` 对缺立绘直接抛
   FileNotFoundError 双保险。满库角色不受萌绘状态影响（取库零绘图）。
3. **种子决定论 + 可编辑库的折衷**：候选按 (pack, id) 排序后取模；用户编辑卷
   会全体重排——接受（换库不追溯，当日 draws 落库的 card_path 回看不受影响）。
4. **handler 传真实 event**：萌绘内部用会话上下文；WebUI 试画（M2，无事件）时
   要另想兜底，不能简单传 None（draw.generate_portrait 已留 event 参数）。
5. **img2img 不带 `workflow` 参数**：那是文生图槽位；图生图工作流走
   `strategy.img2img_workflow`（用户自定义 IPAdapter 工作流的远期挂点）。
6. **负面词内置兜底**：`1boy, male...` 排除男性特征 + NSFW（星语子集）；
   `draw_negative_enabled=False` 时完全不传（含内置），全权交给用户工作流。
7. **`♥` 之类装饰字形不要上卡**：多数 CJK 字体缺字渲染成方块（本次预览实测）。
8. **重抽轨迹必须另开一张表**：`draws` 的覆盖语义是业务需要（一人一天一位），
   但覆盖会抹掉「换老婆前抽到谁」。不要试图给 `draws` 加「历史列」或改成多版本主键
   ——那会污染所有计数口径；用 `draw_events` 只追加，统计照旧读 `draws`。
   **代价**：升级前的轨迹无法回填，UI 要如实说明而不是伪造。
9. **老库迁移只 `ALTER TABLE`**：`Store._migrate()` 先 `PRAGMA table_info` 探测，
   缺哪列补哪列，绝不 `DROP`/重建；插件 data 目录是唯一真源，一次失误就是用户数据全丢。
10. **统计不引重型依赖**：除「UTC→配置时区」的时段分布需要在 Python 里逐行换算，
    其余全走 SQL 聚合；区间由 API 夹在 1~180 天，趋势在 Python 侧补零日。
    不依赖 SQLite JSON1 扩展，也不做缓存 / 预聚合。
11. **前端保持单文件零构建**：`pages/waifu-console/index.html` 是 in-DOM 模板 +
    vendored UMD，加一个 `<script>` 就会撞 `test_html_integrity` 的「恰好 3 个 script」
    守卫。图表因此用**内联 SVG 字符串经 `v-html` 注入**（还顺带避开 HTML 解析器把
    `viewBox` 大小写吃掉），不引 ECharts。要上重型图表就得按星语那样整套迁移到
    `webui-src/` + Vite，那是另一个量级的改动。
12. **「转移」必须搬文件，不能只加引用**（v0.9.1）：立绘与参考图是两套独立列表，
    `/refs/bind` 那种「把 `portraits/...` 路径 append 进 `strategy.refs`」会造成
    两个列表指向同一个 inode——删一边另一边就死链。正确做法是内容寻址另存一份到
    `refs/`、改写所有引用、再删原文件与库行。反向同理，**只解绑当前角色**
    （同一张参考图可能被多角色共用），且仅在全库无引用时删原文件。
    历史脏数据靠 `_delete_portrait_core` 的「引用探测 + 自动另存」兜底。
    路径比较必须走 `_norm_ref` 归一化：refs 里混着绝对路径（上传）与相对路径（绑定）。
13. **调试操作要「先查状态、再给按钮」**（v0.9.2，照抄星语 `pages/debug/index.html`）：
    危险操作不该是一排常驻的独立输入框——用户查的是谁，按钮就该对谁生效。
    所有重置 / 重绘类控件挂在 `v-if="dbgState"` 下，参数从状态结果里取
    （uid / today / 今日老婆 char_id），并在查询时同步给模拟抽签与高级区输入框；
    执行完走 `refreshAfterDebug()` 重新查状态，形成闭环。保留「高级」区是为了
    还能清理其它日期 / 用户 / 角色，但它同样查过状态才显示。
14. **库里存 UTC、UI 显示配置时区**（v0.9.3）：`_now()` 统一产出 `...Z` 是为了
    不受服务器时区影响，别为了显示去改存储格式。显示层用 `fmtTime()` +
    `Intl.DateTimeFormat(timeZone=配置值)` 转 `YYYY-MM-DD HH:mm:ss`，时区由
    `/config` 下发；非法值回落浏览器本地时间。所有时间插值必须走 `fmtTime`，
    契约守卫会扫裸 `{{ ...created_at }}`。
    **群号同理**：`candidates_for` 的规则是「启用卷 ∩ 该群绑定卷 ∩ verified」，
    凡是让用户填 / 选群号的地方都要显示这条口径，且状态查询要把 `group_id`
    一并带给模拟抽签——否则预览按「全部启用卷」算，和真实结果不一致。
    模拟结果返回 `scope`（group_packs / enabled_packs / allow_unverified）把生效范围说清。
15. **刷新停在上次页签靠服务端记忆，桥返回值别多取一层**（v0.10.0）：
    sandbox iframe 无 `allow-same-origin`，localStorage 一碰就抛 SecurityError；
    Dashboard 刷新又按 content_path 重建 iframe src，页内 hash 留不住。所以
    `/ui_state` 落 `data_dir/ui_state.json`，切页 fire-and-forget POST、挂载时 GET
    恢复。桥 SDK **已把 `{status,data}` 信封解包**，`restoreUiMenu` 里再取
    `res.data.menu` 恒为 undefined → 刷新永远落在默认第一页；正确是 `res.menu`
    （兼容写法 `res.menu || (res.data && res.data.menu)`）。页签白名单
    `_UI_MENUS` 与 `menuOpts` 必须逐项同序，契约守卫会扫。
16. **出卡图生图源 ≠ 参考图列表**（v0.10.0，用户口径）：
    `strategy.draw_ref` 是管理员显式指定的、仅用于 `/今日老婆` 图生图的那一张；
    `strategy.ref` 是主参考（试画 / 条目 img2img 画法用）；`strategy.refs`
    只是资料库。**任何自动链路都不许从 refs 里按种子挑图**——旧版
    `generate_portrait` 的「主参考 → refs 随机」兜底会让「没指定图生图参考图」
    的角色也被拿列表里的图重绘。`plan_source` 的 has_ref 只认
    `has_draw_source(draw_ref)`；命中时 `_produce` 把该路径注入 `ref` 再临时转
    img2img；`generate_portrait` 只认显式 `ref`，没有就回退文生图（不报错、
    不私自取图）。解绑 / 转移 / 保活改写 / 引用探测 / 孤儿扫描都要带上
    `draw_ref`，否则出卡源会变死链或被误判成孤儿。
    另有多图源 `strategy.gen_refs`（v0.11.0）：角色详情 / 试画台显式勾选，
    经 `comfyui_img2img.images` 透传（萌绘 v7.8.1+，默认最多 3 张，Qwen 2.1
    等多图工作流按「图1/图2/图3」注入），仍然不碰 `strategy.refs`。

17. **前端是一堆独立快照，写操作必须走统一 refreshAll**（v0.10.1）：
    页面把数据拆成 `meta` / `works` / `currentWork` / `galItems` / `galRefs` /
    `tryRefs` / `drawerRefs` / `ov` / `stats`… 十几份互不相干的 ref，
    `loadAll()` 只刷 `meta`。封面缩略放在 `/pools` 响应顶层的
    `thumbs` / `cover_paths` 字典里（条目本身只有 `cover_path`，**没有
    `thumb`**），所以卡片必须经 `allEntries` 合并出 `e.thumb`，否则设完
    封面永远显示旧图 / 首字母占位。约定：任何写操作后调 `refreshAll()`
    （loadAll + loadWorks + loadGallery + loadGalRefs + tryRefs + drawerRefs +
    overview，并重挂 `currentWork`）；`{full:true}` 额外刷统计/记录/用户/
    调试；`{config:true}` 才重置配置表单。切页签 `watch(menu)` 同样要补
    对应的 load。契约守卫会检查 `allEntries` 的 thumbs 合并、`refreshAll`
    覆盖范围与 7 个关键写操作，别绕过。

18. **人设固装是「整维沉默」，不是「过滤候选」**（v0.35.0）：角色条目的
    `keep_headwear` / `keep_outerwear` / `keep_footwear`（编辑抽屉三个开关）
    经 `prompt_gen.keep_dims_of(entry)` 换算成 keep 集合，在
    `_follow_item` 处直接置空——不是把「摘掉帽子」从候选里去掉。原因：
    女巫的尖顶帽被换成贝雷帽同样是破坏人设，只有整维沉默（本轮不提及头饰、
    外观 tags 也不剥离）才能保证「始终按角色原本设定画」。贯穿四条路：
    `build_generation_prompt`（文生图 / 图生图 / 异常回落三处）、
    `describe_variations`（随档记录，main / webui_api._run_job / batch_fill
    三处调用都要传 keep，否则记录与提示词错位）、`h_prompt_preview`
    （预览镜像链，维度 chip 与提示词同口径）。例外口径：预览面板的
    **显式操作**（锁定 fixed / 重新启用 enabled）不拦——那是管理员当面点的，
    固装拦的是「随机抽中」；穿搭重摇/锁定引发的派生重摇仍拦。
    入库链：编辑表单 → `formToEntry` → `normalize_entry`（布尔归一，旧条目
    缺字段默认 False）→ `merge_saved_entry`（不在 keep_local 名单，随表单
    覆盖）。`effective_entry` 深拷贝条目自动携带，试画 override 无需单列。

19. **顶栏「空闲」必须是查到的空闲**（v0.35.0，v0.34.2 真机教训）：
    文件更新了但插件后端没重载时，旧模块没有 `/queue/list` 路由，轮询一直
    404 被 `pollQueueTop` 静默吞掉，指示器永远显示「空闲」，队列功能没生效
    完全看不出来；且 `_version_of()` 若每次请求重读磁盘 metadata.yaml，
    顶栏版本号会显示新版、继续撒谎。双修复：① 轮询连败 3 次指示器显示
    「不可用」（`.top-queue.broken` 橙色）+ 队列面板顶部 n-alert 说明原因，
    成功一次即恢复；轮询**不走 apiPost**（它失败会弹 message 错误提示，
    3 秒一次是打扰轰炸）且要容忍 bridge 未就绪（首次调用在 setup 同步段，
    mount 前 bridge 是 null）。② `_version_of()` 改为**导入时读一次缓存**
    （`_VERSION_AT_IMPORT`），版本号如实反映「正在运行的代码」。

## WebUI 工坊（v0.10.0 十页签）

`pages/waifu-console/` 单文件 Vue3+NaiveUI + `webui_api.py` 50 条路由。
导航：**总览（第一栏 / 默认页）** / 角色库 / 作品库 / 试画台 /
抽签记录 / 数据统计 / 用户查询 / 调试工具 / 分群绑定 / 配置。
总览数据走 `/overview` 聚合（只读），角色详情、作品详情是二级页面。

后四类页签的分层照抄萌萌星语：handler 只夹参数 + `asyncio.to_thread`，
业务全在同步 `_xxx_core`（脱离 quart 可直测）；列表统一 `{total,page,size,rows}`。
调试里的**模拟抽签是纯 dry-run**，复用真实链路的纯函数但不写库 / 不生图 / 不发消息。
危险操作沿用两段确认（sandbox iframe 无 `allow-modals`，`window.confirm` 恒 false）。

试画事件 = 合成最小 AstrMessageEvent 桩（platform=webui），构造失败回落 None
（萌绘自行回落 _last_event）。

**维度级控制（v0.14.0）**：生成立绘弹窗的维度 chip 可单独重摇（attempts）/ 锁定
（fixed）/ 移除（disabled）/ 启用隐藏维度（enabled），随 `/prompt/preview` 的
`dim_state` 进 `prompt_gen.apply_dim_state`（纯函数）。链条顺序是硬约定：
`pick_variations → img2img 时 force_single_view → apply_dim_state`——面板显式
锁定/启用的 compose 要能覆盖 v0.13.3 的强制单图（只拦随机命中），且
`h_prompt_preview` 里展示用 picks 与 `build_generation_prompt` 内部 picks 必须
镜像同一条链，两处改动要同步（dims 与提示词文本同源）。`dims` 字段保持旧形状
（非空项，试画台只读展示），弹窗用 `dim_control`（全量七维 + fixed/off 标志）；
`/prompt/pools` 给 chip 下拉供池（静态，弹窗首开拉一次）。主题子集靠
「池条目命名自带专属关键词」匹配（swimsuit 原漏「泳衣」、office 原被「西装/马甲」
吸进 JK），每个内容主题 outfit 子集 ≥5 款、background ≥4 项有测试守卫。

③ 预览面板 chip 自动多出「画风」维度，可单独重摇 / 锁定 / 移除；
④ 批量补图的内容主题轮换自动带上 `art_*`（`content_theme_ids` 只排除 random / tpl_）。
img2img 改画风最容易丢脸，指令里额外锚一次辨识度（句尾那条统一约束仍保留）。

**立绘 seq 唯一序列（v0.23.1，替代 v0.15.0 的 MAX+1）**：seq 是「这张图的
唯一 ID」，不是可复用的展示编号。`portrait_seq(char_id, next_seq)` 持久化单调
计数器：实际生成一律 `store.alloc_portrait_seq()` 原子分配（RLock 串行
读→+1→提交，抽卡 / 工坊补图并发不撞号），`next_portrait_seq()` 只读查询供
`h_prompt_preview` 预览（不消耗号，正常情况预览编号 = 实出编号）。v0.15.0 的
MAX+1 在「彻底删除最大 seq 那张」后会回退并复用号 → 同日 `portrait_seed_int`
撞车、归档文件名可能撞；计数器只增不减，删行 / 停用都不回收。允许跳号
（生成失败也消耗一个号），这正是 ID 语义。老库升级在 `_migrate` 里按
`MAX(seq)+1` 播种（`INSERT OR IGNORE`，不重建表）；`add_portrait` 写入时把
计数器推到 `max(next_seq, seq+1)`，兼容外部直接指定 seq 的路径。界面另给
`display_no`（按现存档案 1..N 连续编号，含停用行），卡片 / 详情 / 提示消息
显示它；排序、种子、文件名一律仍用 seq。`count_portraits` 只数启用行，仅用于
配额判定。历史重复 seq 行按 `created_at, id` 决胜排序；前端排序统一收口
`galItemsView`（默认最新在前），后端列表保持 seq 升序（满库取图
`pool_index` 的确定性依赖它，别动）。

**批量补图队列（v0.16.0，batch_fill.py）**：纯函数 `theme_plan`（伪随机主题轮换，
相邻不重复）/ `pick_candidates`（前提筛选）/ `build_tasks` + `BatchRunner`
（插件实例内存态，重启即清）。前提：立绘数不足配额 + 有可用图生图源
（`draw.has_gen_refs`，配置 `batch_require_ref` 可关）。每张走
`prompt_gen`（theme_plan 的主题）→ `draw.generate_portrait`（内部 draw_timeout
兜底单张超时，超时/失败记录后继续）→ archive + `add_portrait(prompt, theme)`。
工坊入口在角色库工具栏「批量补图」弹窗：范围（全部/按卷/按作品/按角色）→
dry-run 预览（含跳过名单）→ 启动/停止/进度轮询。API：`/batch/preview|start|status|stop`。

**⚠️ 工坊 modal slot 纪律（v0.16.0 批量弹窗踩实）**：sandbox iframe + naive
Teleport 下，modal 的 slot 内容是雷区——① 插值/属性表达式里调用方法
（`.join()`/`.map()`/`Math.round`）在数据更新时打断整块渲染（content 静默
清空、无 console 警告）；② `<template v-if>` 子内容更新丢失（v0.13.0 已知坑）；
③ slot 子树 `:key` 重建（key 变化）后 Teleport 内容永久丢失。纪律：弹窗内容
纯 div 布局 + 纯字段插值 + `span v-if`（禁 template v-if），join/map 在后端
拼好（如 preview 的 `themes_text`/`skipped_text`）或收口到 computed
（如 `batchPct`）。**冒烟侧教训**：桩桥 fixture 必须模拟真实状态机
（idle→running），恒返回 running 会让面板按钮全 disabled、点击静默无效，
与「渲染坏了」症状一模一样——先怀疑 fixture 再怀疑代码（v0.13.5 同教训）。

## 注意事项

- 新增顶层模块要同步：`build_zip.ps1` 的 `$includeList`（有守卫会拦）与
  `main.py` 的 `_reload_modules()`。
- 新增 / 改名导航页签要同步：`webui_api.py` 的 `_UI_MENUS`、前端 `menuOpts`、
  `test_webui_contract.py` 的断言（页签记忆白名单不符会被后端拒绝写入）。
- 新增模板变量要同步 setup 的 `return`，并把名字加进 `test_webui_contract.py`
  的 `BINDINGS`（漏暴露在真机上只会静默空白）。
- 热重载生效依赖 main 里**模块属性访问**（pool.xxx 而非 from-import 函数）。
- 打包脚本 ASCII-only（PS 5.1 非 UTF8 代码页会误解析 CJK 注释）。
