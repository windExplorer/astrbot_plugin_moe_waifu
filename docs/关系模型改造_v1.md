# 关系模型改造 v1（分阶段）

> 2026-11-13 定稿。目标：让**全部图片**以及角色、作品、卷都拿到稳定的唯一主键；
> 保留 `hatsune_miku` 这类语义化 `char_id`。最终版本 v1.0.0，分三阶段落地。

## 一、为什么要改

现状是混合模型：抽签/立绘/审计在 SQLite，角色库/作品库在 `data/pools/*.json`
与 `works_meta.json`，图片靠路径字符串互引。后果：

- 只有 `portraits` / `draw_jobs` / `draw_events` 等几张表有自增主键，且 `portraits.id`
  从没被业务当 ID 用（查图走 `(char_id, seq)`、引用走 `file` 路径）。
- 参考图、角色封面、作品封面、卡片图、试画产物没有统一编号；`ref_meta` 只覆盖
  转存/转入的参考图、以路径为主键，手动上传的图没有记录。
- 角色 `id` 是人工/导入给的字符串，作品是 `series` 字符串且 `works_meta.json`
  直接拿作品名当 key —— 改名即断关联，去重只能比字符串。

用户口径（2026-11-13）：库几乎是全新的（抽卡记录空、只有几张立绘），
**允许清空重建**；语义化 `char_id` 保留；**首版只做原神 / 鸣潮 / 异环**，
其余作品等这三个稳定后再纳入。

## 三、表设计

**核心原则：主键（surrogate）与业务键（natural key）分开。**

- 每张表都有自增整数主键，这是「数据库常规操作」要求的唯一编号；
- `char_id` / `series` 等语义化字符串继续作 `UNIQUE` 自然键，用于抽签种子、
  候选排序、日志、工坊 API、跨插件引用。**不换成数字主键**，否则抽卡结果、
  历史记录、导入/去重契约全要跟着改，收益几乎为零。

| 表 | 主键 | 关键列 / 约束 |
| --- | --- | --- |
| `assets` | `id INTEGER PK AUTOINCREMENT` | `kind`（portrait/ref/cover/card/try）、`path TEXT UNIQUE`、`sha256`（内容去重）、`width/height`、`created_at` |
| `packs` | `id` | `name UNIQUE`、`title`、`enabled` |
| `works` | `id` | `name UNIQUE`（作品名）、`category`、`color`、`cover_asset_id → assets.id` |
| `characters` | `id` | `char_id TEXT UNIQUE`、`pack_id → packs.id`、`work_id → works.id`、`name`、`tags_en`、`verified`、`strategy_json`、`cover_asset_id` |
| `portraits` | 既有 `id` | 补 `asset_id → assets.id`；`char_id` 保持自然键 |
| `ref_meta` | 保留 | 逐步并入 `assets`（本阶段不删，双写） |

`assets` 覆盖**全部图片**：立绘、`refs/` 参考图、角色/作品封面、`cards/` 卡片、
`try_cache/` 试画成品。同一内容用 `sha256` 去重，不同类型引用同一个 `asset_id`
是允许的（例如一张立绘被设为角色封面，不再产生第二条资产记录）。

## 四、分阶段

### 阶段 1（本版 v0.24.0，只加不拆）

- 建四张表 + `portraits.asset_id` 补列（PRAGMA 探测 + ALTER，不重建表）。
- 幂等迁移器：启动时从 `pools/*.json` 解析入库，只纳入三个作品；扫描 data 目录
  把现存图片登记进 `assets`；重复启动不产生重复行。
- `add_portrait()` 写入时登记 `assets` 并回填 `asset_id`。
- 工坊只读状态接口 `/relational/status` 展示各表数量，`portraits/list` 返回
  `asset_id`。
- **现有读写路径一律不动**：JSON 仍是真源，抽卡/工坊行为完全不变，新表是地基。

### 阶段 2（切读路径）

`load_packs` / `candidates_for` / `find_entry` / 作品库聚合改从新表读，
JSON 降级为只读兜底。此时抽卡候选从 145 条收敛到 128 条 —— 用户库全新、
无历史签要追溯，可接受。**候选排序键保持 `(pack, char_id)` 自然键不变**，
避免决定论再受影响。

### 阶段 3（切写路径 → v1.0.0）

工坊 CRUD、导入、去重、作品封面、参考图绑定全部改写新表；
JSON 降级为「种子卷 + 导入导出格式」。手工改卷 JSON 的能力会失去，
补「导出整卷」按钮补偿。

## 五、兼容与回滚

- 卷 JSON / `works_meta.json` / 图片文件全程**不删**，迁移只增不减；
- 迁移器幂等，随时可重新跑；新表可整体重建；
- 阶段 1 不改任何现有行为，出问题只需停用地基（回退到上一版 zip）；
- `dist/` 历史包按工作区规范保留，便于回退。

## 六、风险

1. 阶段 2 候选集变化会改全体排名（决定论与可编辑库的固有折衷）；
2. 阶段 3 改动面覆盖工坊全部读写，必须逐接口回归；
3. 语义化 `char_id` 仍可能跨卷重复（现有去重工具按并查集处理，阶段 3 靠
   `characters.char_id UNIQUE` 从根上堵住）。
