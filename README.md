# ♥ 萌萌今日老婆

> 适用于 AstrBot 的每日二次元老婆抽卡插件：每天从角色库里确定性抽出一位「今日老婆」，
> 萌绘生成专属立绘（并沉淀进立绘库），渲染成萌系竖版卡片发到群里。

![依赖](https://img.shields.io/badge/%E7%A1%AC%E4%BE%9D%E8%B5%96-%E8%90%8C%E7%BB%98%20v7.7.58%2B-red)

---

## ⚠️ 硬依赖：萌绘（先读这段）

本插件的立绘由 **萌绘（`astrbot_plugin_comfyui_anima`）** 生成，属于**硬依赖**：

- 请先安装并配置好萌绘（**v7.7.58 及以上**）与 ComfyUI 后端，再使用本插件；
- **需要生图而萌绘不可用（未安装 / 超时 / 失败）时，插件会报错且不出卡**——
  立绘就是产品本体，我们刻意不做「无图的降级卡片」；
- 角色立绘攒满配额后，从立绘库直接取图，**不再需要萌绘在线**；
- 生图走萌绘统一的跨插件契约（`external=True`），画风 / LoRA / 工作流 / 图库
  全部由萌绘统一管理，本插件不会自行连接 ComfyUI。

## 玩法

| 指令 | 说明 |
| --- | --- |
| `/今日老婆`（别名 `/老婆`） | 抽今天的老婆。一人一天一位：种子（日期+用户号+盐）决定，重启不变、无法刷 |
| `/换老婆` | 重新抽一位。受「每日换老婆次数」限制（默认 1 次，可配 0=关闭） |
| `/老婆帮助` | 帮助 |

**角色库管理 / 试画 / 立绘库维护 / 抽签记录 / 统计 / 用户查询 / 调试都在 WebUI「工坊」里做**：
AstrBot Dashboard → 插件 → 萌萌今日老婆 → 打开插件 Page（仅管理员）。
试画不走聊天指令，详见下方「WebUI 控制台」。

**卡片内容**：角色立绘全幅打底 + 角色应援色渐变面板：名字、作品、分类/稀有度徽章、
一句印象语、「今日同款 N 人」（本群今天抽到同一角色的人数）、「第 N 次抽到她」（累计）、
日期与重抽标。

**同款机制**：同群同日抽到同一角色的人，共享同一张立绘、互相可见——这是话题来源，
不是竞争机制。

## 立绘库（核心机制）

每个角色有一个立绘配额（默认 5 张）：

- **未满配额**：当天第一个抽到她的人触发生成（萌绘 20~120 秒，会先发「正在召唤」提示），
  成功后**存档入库**；当天再有人抽到 → 直接复用这张图；
- **满配额**：按种子从库存随机取一张，**零绘图秒出**，完全不消耗 ComfyUI 算力；
- 立绘只增不淘汰；后续版本的工坊页可以删掉画坏的图，删除后低于配额会自然补生。

## 角色库（一卷一 JSON）

角色库在 `data/plugin_data/astrbot_plugin_moe_waifu/pools/`，**一个 JSON 文件 = 一卷**：

```json
{
  "pack": "anime",
  "title": "动漫卷",
  "enabled": true,
  "entries": [
    {
      "id": "hatsune_miku",
      "name": "初音未来",
      "series": "VOCALOID",
      "category": "anime",
      "tier": "S",
      "strategy": {"type": "base"},
      "tags_en": "hatsune miku, twintails, teal hair, headset, sleeveless shirt",
      "quote": "初次见面，我是初音未来！",
      "color": "#39C5BB",
      "verified": false
    }
  ]
}
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `category` | `anime` 动漫 / `gal` galgame / `game` 游戏 / `other` 其他 |
| `tier` | 仅作卡片徽章展示（S/A/B…），不参与抽卡权重 |
| `strategy` | **画法策略**：`base`（底模认识的角色 tag 直出）/ `lora`（`{"type":"lora","loras":["xxx:0.8"]}`）/ `img2img`（`{"type":"img2img","ref":"<官方立绘 URL 或本地路径>"}`） |
| `tags_en` | 英文 danbooru 角色标签（角色 tag + 系列 tag + 稳定外观特征）。括号要写成 `\(` `\)` 转义 |
| `verified` | 试画验证过「画得对」才参与抽卡（可在配置里放宽） |
| `color` | 角色应援色（hex），整张卡随它定色 |

**怎么保证画对？** 策略是试出来的，不是配置出来的：

1. 在工坊「试画台」选角色试画——动漫 / 二游主流角色底模基本都认识（base 一步过）；
2. 画错了（不像本人）→ 在「角色库」补正 tags，或把策略改成 `img2img` 挂一张官方立绘
   参考图（干净单人图，组图/Q版不可用），重绘强度默认 0.65，再试；
3. 画对了 → 试画台点「画对了，标记 verified」，从此参与群内抽卡；也可以
   「存入立绘库」提前沉淀。

工坊九页签：**角色库**（增删改查 / 分卷分类筛选 / verified 开关）、**作品库**、
**试画台**、**抽签记录**、**数据统计**、**用户查询**、**调试工具**、
**分群绑定**（每行 `群号=作品,作品`）、**配置**。角色详情 / 作品详情是二级页面，
不占导航位。立绘库在角色详情里（缩略图网格 / 删坏图 / 单角色补一张）。

首启时包内自带 20 条种子卷（动漫 8 / gal 4 / 游戏 8）会复制到 data 目录
（**已有的卷不会被覆盖**），此后 data 目录就是唯一真源，升级插件不丢库。

**分群角色库**：配置 `group_pools` 每行一条 `群号=作品,作品`，该群就只在指定作品里抽；
留空 = 全部启用卷。

## WebUI 控制台：记录 / 统计 / 用户 / 调试

四个独立页签（仅管理员，Dashboard 登录墙内）。参照[萌萌星语](https://github.com/windExplorer/astrbot_plugin_moe_star_whisper)的口径，
不引重型图表库，全部用内联 SVG + CSS 画。

| 页签 | 能做什么 |
| --- | --- |
| **抽签记录** | 日期区间（近 7/30/90 天快捷）、QQ / 昵称 / 角色名关键词、群 / 角色 / 平台 / 首抽重抽筛选，分页表格；点 QQ 号跳用户查询，点「详情」看种子、角色快照、立绘来源、**当天重抽轨迹**（换老婆前是谁）与相关出图任务；卡图可直接放大。另有抽签流水表与生成任务审计表 |
| **数据统计** | 7/30/90/180 天区间、8 张指标卡；每日趋势折线（抽签数 / 独立用户 / 成功出图）、24 小时时段分布（按配置时区换算）、角色热度 Top12、群 / 私聊占比环图、立绘来源与出图质量 |
| **用户查询** | 按最近 / 抽签数 / 老婆数 / 重抽数排序，搜索 QQ 或昵称；单用户档案含当前连签与最长连签、今日老婆、近 3 个月抽签日历（格子是当天老婆的应援色）、老婆偏好、历史签与抽签流水 |
| **调试工具** | 输入 QQ 号查状态（今日签 / 关键配置快照 / 流水 / 任务 + 最近查过的 uid），**查到状态后才出现**「今日签操作」卡：强制换签、重置今日记录、重绘卡片、重试今日老婆立绘、清空老婆立绘库——全部自动带好当前 QQ 与今天，两段确认，执行后状态 / 记录 / 审计自动刷新；另有 **只读模拟抽签**（指定 uid / 日期 / nonce / 盐 / 群，不写库不生图不消耗换老婆次数）、用于其它日期 / 用户 / 角色的「高级」区、操作审计 |

**立绘 ↔ 参考图是「转移」不是「关联」**：点立绘卡上的右箭头，文件从 `portraits/`
另存到 `refs/`，立绘列表里立刻移走；参考图卡上的左箭头反向转回。两个列表互斥、
文件各自独立，删一边不影响另一边。同一张参考图被多个角色共用时，转回只解绑当前角色，
不会牵连别人。v0.7.5~v0.9.0 曾把立绘路径直接绑成参考图（两个列表指向同一文件）；
这类历史数据在删除立绘时会自动另存一份到 `refs/` 保住参考图。

**统计口径**：一人一天一行（`draws` 主键 `(user_id, date)`），重抽覆盖当天结果、
不重复计入人数；「重抽次数」取当天签的 `nonce` 之和，「流水重抽事件」另算，
升级前的历史数据没有流水时两者会不一致。群归属取该签最后一次记录的群，私聊单独归类。

**时间显示**：流水 / 任务 / 审计 / 详情里的时间一律按插件配置的 `timezone` 显示成
`YYYY-MM-DD HH:mm:ss`；库里存的是 UTC `...Z` 时间戳，不再裸显（也不再早 8 小时）。

**群号口径**：抽签候选始终是「启用卷 ∩ 该群绑定作品 ∩ verified」，未列出的群 /
私聊用全部启用卷。记录筛选与模拟抽签都遵循这条规则；调试页查过状态后会自动带出
该 QQ 今日签的群号，模拟结果还会显示实际生效的卷与候选数，不用盲填群号。

## 配置项（插件配置页）

| 配置 | 说明 | 默认 |
| --- | --- | --- |
| 时区 | 「今天」按此时区计算 | Asia/Shanghai |
| 种子盐值 | 与日期、用户号一起派生结果，勿随意改 | moe-waifu |
| 停用群 | 每行一个群号 | 空（全开） |
| 分群角色库 | 每行 `群号=作品,作品` | 空（全作品） |
| 每日换老婆次数 | 0 = 禁用换老婆 | 1 |
| 每角色立绘配额 | 满了之后从库里取图不再生图 | 5 |
| 未验证角色可抽 | 关闭时只有 verified 角色会被抽到 | 关 |
| 生图工作流 | 留空用萌绘默认 | 空 |
| 立绘尺寸 | 生成图与卡布一致 | 700×1200 |
| 生图超时 | 超时报错不出卡 | 120 秒 |
| 负面提示词 | 内置兜底排除男性特征与 NSFW，可覆盖 | 内置 |
| 重绘强度 | img2img 策略用 | 0.65 |
| 召唤提示 | 生成时先发一句过程提示 | 开 |

## 安装

1. 安装并配置 **萌绘 v7.7.58+** 与 ComfyUI 后端（`external` 跨插件契约自该版本引入）；
2. 通过 AstrBot 插件市场或 zip 安装本插件，重启 AstrBot；
3. 发 `/今日老婆` 验证：首张卡生成需要等萌绘（20~120 秒），之后同角色当日秒出。

## 数据与文件

- 库文件：`data/plugin_data/astrbot_plugin_moe_waifu/waifu.db`（SQLite，WAL）
  - `draws` 当日结果（一人一天一行，重抽覆盖）、`draw_events` 只追加的抽签流水、
    `user_char_counts` / `char_stats` 计数、`portraits` 立绘库存档、
    `draw_jobs` 生图审计、`debug_history` 调试审计（环形 200 条）
  - v0.9.0 起老库会就地 `ALTER TABLE` 补 5 列，不重建、不丢数据
- 角色库：`data/plugin_data/astrbot_plugin_moe_waifu/pools/*.json`
- 立绘库：`data/plugin_data/astrbot_plugin_moe_waifu/portraits/<角色id>/*.png`
- 卡图：`cards/<用户>_<日期>.png`（保留 90 天）；试画缓存 `try_cache/`（7 天）
- 参考图（img2img）：条目 `strategy.ref` 支持 URL 或本地路径

## 已知边界

- **v0.9.0 之前的重抽轨迹无法回填**：那时 `draws` 是覆盖更新，换老婆前的角色没留档；
  升级后每次抽 / 重抽都会同时写一条 `draw_events`。老记录仍可查，只是「详情」里
  会显示「该签早于 v0.9.0，没有流水」。
- `img2img` 参考图仅本地缓存用于生图，不会二次配布；
- `base` 策略的效果取决于萌绘所配底模对 danbooru 角色 tag 的认知
  （推荐 NoobAI / Illustrious 系动漫工作流）；
- 未配置verified 角色前，若库里没有可用角色会提示「老婆库还是空的」。
